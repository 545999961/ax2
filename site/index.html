01 /The research question

The first answer
is only the beginning.

Hard problems rarely yield to one attempt. An agent needs to try, measure, and revise—and know what to do when a revision fails.

We call this self-improvement: the ability to turn more rounds on a single task into a better solution, at test time. Not just a stronger first answer. A stronger process for reaching the next one.

This is iteration within a task, not weight updates or the accumulation of memory across test-time tasks.

Read the abstract

We present AREX 2.0, an effort to advance the self-improving capability of LLM agents, defined as the ability to iteratively refine a solution at test time. This ability rests on two capabilities: reflection, which produces a better solution than the current one, and long-horizon execution, which sustains effective iteration. We hypothesize that both are domain-agnostic and can be learned from scenarios well suited for supervision. We therefore synthesize long-horizon improvement trajectories from machine learning and algorithmic programming tasks, which offer verifiable feedback and reward sustained iteration. Trained on this data, our Qwen3.8-27B-based agent achieves strong results on MLE-bench Lite (81.8) and Frontier-CS (70.7), transfers to deep research with 84.0 on BrowseComp and 52.6 on HLE, and improves more steeply as iterations increase. These results show that long-horizon reflective data is an effective route to self-improving agents.

02 /The training ground

Keep the journey.
Not just the answer.

A successful answer does not show how it was reached. We build data that does. Our hypothesis: long-horizon reflection is a transferable skill, best learned where progress is easy to measure.

03 /The method

How we teach
the improvement loop.

Build environments with headroom. Let capable agents work. Learn from the complete record.

01

Make progress measurable.

A teacher turns repositories and judge problems into tasks, sandboxes, and scoring functions. Execution checks establish that each environment works—and that a baseline has room to improve.

Admit only valid environments with headroom.

02

Give the agent a real horizon.

Long budgets make room for measurement, experiments, and revision. Operational knowledge and feedback help the teacher decide what to keep, what to revert, and what to try next.

Hours of work. Hundreds of tool calls. Feedback in the loop.

03

Select outcomes, not perfect paths.

A run is selected as a whole for a strong result and a valid process. Intermediate regressions are not a reason to remove it. Their diagnoses and recoveries are part of what the model needs to learn.

Retain failures, reversions, and changes of strategy.

04

Learn the decisions that matter.

Imitate informative agent decisions in the full trajectory context: hypotheses, edits, experiments, diagnoses, repairs, and submissions. Observations provide context; redundant polling receives no loss.

Fine-tune Qwen3.8-27B with the combined data.

New ML + programming trajectories+Unchanged AREX deep-research data→AREX 2.0 / 27B

Improvement is
a learned behavior.

Better reflection makes each revision count. Long-horizon execution keeps the process useful. Training on the complete journey gives agents a way to learn both.
